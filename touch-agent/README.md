# MirrorGoodGood Touch Agent 1.7.0

Pinned public Appium WebDriverAgent 12.0.0 with independent USB-only control endpoints. Minimum iOS 16. Compile on macOS 15 / Xcode 16.4, unsigned IPA; sign locally with your own account, retaining the nested XCTest bundle and frameworks. Host bundle remains com.jinghaohao.touch.runner.

The optimized /jhh/v1/keys endpoint takes one fresh standard XCTest system keyboard snapshot per request, matches key labels in memory, validates geometry against XCTest keyboard anchors, and submits a single sequential tap record. Batches are bounded to eight plain letters. Space, deletion, Return, modifiers, numbers and symbols are single-key barriers; the first letter after a layout boundary is also alone. Single-key layout switches use the existing explicit slow path before any fast event is submitted. No uncertain request is retried.

Geometry cache 1.5.0 checks app PID, orientation, screen bounds, native bounds and scale on every request. For gestures it validates the root frame every five seconds instead of rebuilding three XCTest anchors on a timer. Matching frames retain the original affine coordinate basis; a mismatch rebuilds it. Full anchor calibration is bounded to at most 60 seconds. The keyboard validates its fresh snapshot frame on every batch. All cache clocks use monotonic uptime. Frame changes within a gesture validation interval can still require the next validation, as with the previous five-second cache. Desktop preview resize is a local mapping operation and is not a phone cache invalidation. Key snapshots or input fields are never cached. Native-keyboard mode uses key taps. Committed-text mode uses a separate redacted text event; neither mode discovers or assigns an input field or injects a clipboard. Chinese uses the iPhone system 26-key Pinyin keyboard; choose candidates on the mirrored phone.

The desktop collects press transitions without waiting for the phone, preserving every key in a bounded per-device queue. Unsent keys are cleared on device switch, focus loss, geometry change, overflow or expiry. Disconnect never replays old input. Sequence and instance checks apply across gesture and keyboard requests. Only selected-device USB forwarding is used. The service binds 127.0.0.1:8100, has no screenshot broadcaster and exposes status, gesture, legacy key, bounded keys, and committed-text routes.

Build and simulated throughput checks do not establish real-phone latency. Actual English/Pinyin input, layout mapping and iOS 16 latency must be measured after signing and installation. Desktop GPL-3.0-only, new patches BSD-3-Clause; upstream and dependency licenses ship with corresponding source. No credentials are uploaded.

Version 1.6 uses a fresh standard snapshot instead of the custom accessibility query and keeps 35 ms presses with 45 ms start spacing (previously 60 ms). Plain number-row/keypad 1-9 after letter input select recognized visible Chinese candidate items left to right, as a single-key semantic barrier. Zero, shifted symbols, and no-candidate numeric entry retain ordinary key behavior. Screen gestures, app changes, candidate selection and semantic commits reset local composition expectation. Candidate text/targets are never cached or logged. Candidate geometry and CJK/filter/order/dedup policy are tested as compiled production C; actual iOS candidate accessibility and numeric selection require real-phone validation after signing. Unsupported/hidden candidate items are not guessed.

Version 1.7 adds /jhh/v1/text for committed Unicode and separately validated editing keys. It synthesizes a text-input path to the current keyboard focus without finding or assigning an input-field element. The event name is fixed and text is redacted; no payload appears in metrics. Keyboard visibility is checked first. Commits reject control/newline characters, invalid UTF-16, oversized strings and WebDriver private key codes. Enter/Tab/delete/arrows require explicit editing-key requests. Sequence consumption precedes synthesis; uncertain writes are never replayed. Windows IME mode suppresses raw Pinyin/digit HID events, cancels unsent commits on source change and preserves failed text for manual recovery. Actual iOS and app compatibility requires signing/installing and real-device testing.

## v1.8.0 photo upload
Adds USB-only PhotoKit add-only image upload on the existing lightweight runner; no second XCTest instance. Only after PhotoKit confirms success is an image counted saved. Hashes and image type are checked; uncertain commits are never repeated. Legacy /wda/jhh/photos paths are preserved for the public photo client. Signing and real phone permission/import remain user installation tests.

## v1.9.0 execution receipts
Reads the actual XCTest completion BOOL and safe pre/post keyboard/focus flags, including app-change detection. A hidden keyboard with observed editing focus remains usable. Unknown outcomes retain text on desktop; no automatic repeat, fallback, field mutation or message sending. No field values/labels or submitted text are logged. Insertion remains unverified even when event execution succeeds. Requires real iPhone/Xianyu validation after signing.

## v1.9.1 JSON boolean encoding fix
The v1.9.0 comparison was boxed as an Objective-C integer, emitting 1/0 instead of true/false. Production now uses explicit NSNumber booleans. A macOS Foundation serialization test reproduces the old encoding and validates the real new helper; json-codec-proof.json ships with the build. Desktop supports the narrowly identified old committed-text receipt while retaining all event, app and context guards. UTF-8 is explicit for the desktop worker. Real app text insertion is still not verified by receipt alone.


Clipboard 1.10.2: requires the actual XCTest host PID and active UIKit state; writes an NSString using the standard local-only object API with a ten-minute expiry. Clipboard availability is checked before one stationary three-finger editor tap; only a unique enabled Paste menu/toolbar item may be invoked. No long press, pinch fallback, permission acceptance, Send action, or automatic replay. Receipts never claim verified insertion. Physical-device compatibility remains unverified for this revision.
